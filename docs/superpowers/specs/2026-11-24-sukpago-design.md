# 석파고(SukPaGo) 설계

- 작성일: 2026-11-24
- 용도: 학교 파이썬 창작대회 출품작
- 요약: 교수님이 한국어로 말하면 문장 단위로 알아듣고, 몽골어·중국어·영어로 번역해 화면 맨 앞에 크게 띄우는 윈도우용 프로그램. 자주 쓰는 안내 문장 5개는 버튼 하나로 띄우고 소리로도 읽어 줍니다.

## 1. 목표와 제약

| 항목 | 내용 |
|---|---|
| 실행 환경 | Windows 10/11 64비트. 개발은 맥에서 하지만, 판단과 검증은 윈도우 기준 |
| 배포 | GitHub Actions가 만드는 zip. 압축을 풀고 `SukPaGo.exe`를 실행하면 끝 |
| 파이썬 | uv로 관리. Python 3.13 고정 |
| 비용 | 카드 등록 없음. API 키 없음 |
| 메모리 | 오프라인으로 전부 켰을 때 최대 2GB 이하 |
| 언어 | 원문은 한국어. 번역은 몽골어(키릴 문자, 할하 방언), 중국어(간체), 영어 |

## 2. 기능

1. **실시간 강의 번역** (핵심 기능)
   - [🎤 시작] 버튼을 누르면 마이크 입력을 받습니다.
   - 말하는 도중에는 한국어 인식 결과가 회색 "임시 자막"으로 계속 바뀝니다.
   - 교수님이 말을 멈추거나 문장이 끝나면 한국어 문장과 번역이 확정되어 목록에 쌓입니다.
   - 음성 인식을 대체 엔진(SenseVoice)으로 쓰면 임시 자막은 나오지 않고 확정 문장만 나옵니다.
   - 메인 창에는 최신 문장 하나만 크게 보여 줍니다. 지난 문장 전체 기록은 번역 전용 창에서 봅니다.
2. **고정 문장 버튼 5개**: 떠들지 마세요 / 집중하세요 / 이해됐나요? / 질문 있나요? / 질문 없으면 넘어갈게요
   - 미리 검수한 번역(`phrases.json`)과 빌드 때 미리 만든 음성 wav를 씁니다.
   - 모델도 네트워크도 쓰지 않기 때문에 누르는 즉시 뜨고 소리가 납니다.
   - **내 문장 추가**: 선생님이 자주 하는 말을 직접 등록하면 버튼 줄 끝에 "내 문장" 표시와 함께 생깁니다.
     - 번역은 추가할 때 한 번만 합니다(온라인이면 MyMemory, 아니면 오프라인 엔진). 결과는 TTS wav와 함께 사용자 폴더의 `custom_phrases.json`에 저장합니다.
     - 그 뒤로는 고정 문장과 똑같이 바로 뜹니다.
     - 등록된 문장은 목록에서 지울 수 있습니다.
3. **직접 입력 번역**: 한국어 입력창에 쓰고 Enter를 누르면 번역합니다. 마이크가 없을 때나 시연할 때 씁니다.
4. **언어 토글 3개** (몽골어/중국어/영어)
   - 여러 개를 동시에 켤 수 있고, 켜진 언어마다 결과가 한 줄씩 나옵니다.
   - 최소 하나는 켜져 있어야 합니다.
5. **온라인/오프라인 토글 1개**: 번역과 TTS의 엔진만 바뀝니다. 음성 인식은 항상 오프라인입니다(키 없이 쓸 수 있는 온라인 음성 인식이 없음).
   - 온라인 호출이 실패하거나 한도를 넘으면, 그 요청만 오프라인으로 처리하고 상태 표시줄에 "오프라인으로 전환됨"을 띄웁니다. 토글 상태는 바꾸지 않습니다.
6. **TTS 읽어주기**
   - 고정 문장과 직접 입력 결과는 켜진 언어 순서(몽골어 → 중국어 → 영어)대로 읽습니다.
   - 실시간 강의 모드에서는 기본값이 꺼짐입니다. 교수님 말과 기계 음성이 겹치기 때문입니다. [🔊 실시간 읽기] 토글로 켤 수 있습니다.
   - 결과 줄마다 다시 듣기 버튼이 있습니다.
   - 새 음성이 시작되면 재생 중이던 소리는 멈춥니다.
7. **항상 맨 앞**: 창은 `topmost`로 다른 창 위에 뜹니다. 📌 버튼으로 끄고 켤 수 있고, 기본값은 켜짐입니다.
8. **번역 전용 창**
   - 메인 창의 [번역 창 띄우기] 버튼으로 엽니다. 번역문만 크게 보여 주는 별도 창이라 프로젝터나 두 번째 모니터에 띄우는 용도입니다.
   - 메인 창의 언어 토글을 그대로 따릅니다. 한국어 원문, 버튼, 입력창은 없습니다.
   - **전체 기록**: 이번 실행에서 나온 문장을 모두 보여 줍니다. 오래된 문장이 위, 최신 문장이 아래입니다.
     - 번역문과 언어 코드(MN/ZH/EN)만 표시합니다. 시간, "최신" 같은 배지, 안내 문구는 넣지 않습니다. 글자 자리를 차지하기 때문입니다.
     - 최신 문장은 설정한 글자 크기로 표시합니다.
     - 바로 앞 3문장은 학생이 흐름을 따라올 수 있도록 밝은 글씨로, 최신 문장 크기의 75%(보통)로 표시합니다.
     - 그보다 오래된 문장은 그 80% 크기의 흐린 글씨로 표시합니다.
     - 이전 문장 크기는 도구 줄의 [작게 55% / 보통 75% / 크게 90%]로 바꾸고, `settings.json`에 저장합니다.
     - 화면은 글자에 최대한 내줍니다. 창 가장자리 여백은 8px, 문장 사이 간격은 0, 줄 간격은 1.18로 둡니다. 언어 코드는 글자 앞에 작게 붙이고 따로 칸을 잡지 않습니다. 도구 줄 위아래 여백도 최소로 둡니다.
     - 새 문장이 오면 맨 아래로 자동 스크롤합니다. 사용자가 위로 스크롤해 둔 동안에는 자동 스크롤을 멈춥니다.
   - **문장 클릭**: 그 문장을 최신 문장과 같은 크기로 키우고 테두리로 강조한 뒤, 켜진 언어로 읽어 줍니다.
     - 다시 누르거나 [최신 문장으로] 버튼을 누르면 원래대로 돌아가고 맨 아래로 이동합니다.
   - **글자 크기**: [A−]/[A+] 버튼(8px씩), 슬라이더, `Ctrl` + 마우스 휠로 24~120px 사이에서 바꿉니다. 기본값은 52px입니다.
   - 이 창도 기본으로 맨 앞에 뜨고, 📌 버튼이 따로 있습니다.
   - 글자 크기와 창 위치·크기는 `settings.json`에 저장합니다.
   - 기록은 메모리에만 두고 프로그램을 끄면 사라집니다(최대 500문장).
9. **용어 고치기**: 메인 창에서 "인식된 말 → 바꿀 말"을 등록합니다(예: 노트북 에램 → NotebookLM).
   - 등록 즉시 이후 문장부터 문장 정리 단계에서 치환됩니다.
   - Zipformer를 쓸 때는 바꿀 말을 핫워드로도 넘겨서 인식 단계부터 잘 알아듣게 합니다.
   - 목록에서 지울 수 있고, 사용자 폴더의 `glossary.json`에 저장합니다.
10. **마이크 상태**: 메인 창에서 마이크를 고르고 입력 소리 크기를 막대로 봅니다.
    - 말하는 구간의 평균 크기가 너무 작거나(−40dBFS 미만) 너무 크면(클리핑 1% 이상) 노란색·빨간색 안내를 띄웁니다.
    - 고른 마이크는 `settings.json`에 저장합니다.

## 3. 엔진

엔진은 모두 공통 인터페이스 뒤에 두고, 어떤 엔진을 쓸지는 `engines.json`에서 정합니다. 그래서 모델 평가 결과에 따라 코드를 고치지 않고 엔진을 바꿀 수 있습니다.

| 역할 | 1순위 후보 | 대체(이미 테스트함) |
|---|---|---|
| 음성 인식 (오프라인) | `kangkyu/icefall-asr-ko-streaming-zipformer-174m` int8 (sherpa-onnx 스트리밍, 자유 발화 KsponSpeech CER 7.5%, Apache-2.0) | SenseVoice int8 **2024-07-17** + silero VAD (sherpa-onnx) |
| 번역 (온라인) | MyMemory `api.mymemory.translated.net/get` (키 없음, `de=` 이메일은 설정에서 선택) | – |
| 번역 (오프라인) | Tencent Hy-MT2-1.8B Q4_K_M GGUF (llama-cpp-python CPU, Apache-2.0) | NLLB-200 distilled 600M int8 (CTranslate2, CC-BY-NC) |
| TTS (온라인) | edge-tts: `mn-MN-YesuiNeural`, `zh-CN-XiaoxiaoNeural`, `en-US-JennyNeural` | – |
| TTS (오프라인) | sherpa-onnx **1.13.x**: 몽골어 MMS `mon`, 중국어 Piper `zh_CN-xiao_ya-medium-int8`, 영어 Piper `en_US-amy-medium-int8` | – |

**언어 코드**

| 언어 | MyMemory | NLLB | Hy-MT2 프롬프트 | edge-tts |
|---|---|---|---|---|
| 한국어 | `ko` | `kor_Hang` | Korean | – |
| 몽골어 | `mn` | `khk_Cyrl` | Mongolian (Cyrillic script, as used in Mongolia) | `mn-MN` |
| 중국어 | `zh-CN` | `zho_Hans` | Simplified Chinese | `zh-CN` |
| 영어 | `en` | `eng_Latn` | English | `en-US` |

**지금까지 확인한 사실과 주의할 점** (2026-11-24, 맥에서 플랫폼과 무관한 부분만 확인)

- **MyMemory**
  - 키 없이 ko→mn/zh-CN/en 호출이 성공했고, 몽골어는 키릴 문자로 나왔습니다.
  - 수업 문장은 NLLB보다 훨씬 정확했습니다.
  - 하루 한도는 IP당 5,000자이고, 이메일을 넣으면 50,000자입니다. 학교 와이파이처럼 IP를 공유하면 한도도 같이 씁니다.
- **NLLB-600M**
  - 영어는 쓸 만했습니다.
  - 몽골어와 중국어는 자주 틀렸습니다(화요일→월요일, "양분"→"술 취함" 등).
  - 길고 지저분한 입력에서는 같은 말을 반복하는 경우가 있었습니다.
  - 음성 인식과 함께 올렸을 때 맥에서 측정한 최대 메모리는 2.2~2.5GB로, 예산을 넘었습니다.
- **SenseVoice 2024-07-17**
  - 실제 강의 3분 분량을 2.3초에 인식했습니다(실시간보다 약 80배 빠름).
  - 문장부호와 띄어쓰기는 나오지만, 자유 발화는 오류가 많았습니다(NotebookLM → "노트북 에램").
  - 2025-09-09 판은 한국어 인식이 망가져 있으므로 쓰지 않습니다.
- **Hy-MT2**
  - 몽골어가 키릴 문자로 나오는지 확인되지 않았습니다. 내몽골 전통 문자(U+1800–18AF)로 나올 가능성이 있습니다.
  - 공식 저장소의 1.25비트·2비트 GGUF는 x86에서 쓸 수 없습니다. Q4_K_M만 씁니다.
  - llama-cpp-python은 PyPI에 소스 패키지만 있습니다. 공식 wheel 저장소(`abetlen.github.io/llama-cpp-python/whl/cpu`)에서 받습니다.
- **sherpa-onnx는 1.13.x로 고정합니다.** 2.0.3에서는 Piper 영어 모델이 실패했습니다. 1순위 음성 인식 모델도 1.13.x에서 돌아가는지 평가 단계에서 확인합니다.
- **MMS 몽골어 TTS는 `ө` 대신 `ѳ`(U+0473)를 씁니다.** 합성 전에 `ө→ѳ`, `Ө→Ѳ`로 바꿔야 합니다.
- **라이선스**: NLLB와 MMS는 CC-BY-NC 4.0(비상업)이라 학교 대회에는 문제없습니다. zip에 `THIRD_PARTY_NOTICES.txt`를 넣습니다. HY-MT1.5는 라이선스가 한국을 제외하므로 쓰지 않습니다.

## 4. 모델 평가 단계 (구현의 첫 단계)

1순위 후보는 아직 직접 돌려 보지 않았습니다. 그래서 구현은 평가부터 시작합니다.

- **도구**: `tools/evaluate.py`
- **입력**: 학생이 직접 녹음한 실제 강의 3개(각 앞 3분, 16kHz wav). 녹음 파일은 저장소에 넣지 않고 `eval_data/`(gitignore)에 둡니다.
- **음성 인식 비교**: 후보마다 다음을 출력합니다.
  - 문장별 인식 결과
  - 실시간 배율(RTF)
  - 최대 메모리
  - 띄어쓰기 유무
  - 핫워드(예: NotebookLM) 적용 전후 결과
- **번역 비교**: 인식된 문장 중 10개를 고르고, 후보마다 3개 언어 결과를 나란히 출력합니다.
  - 몽골어 출력에 전통 문자 범위(U+1800–18AF)가 있으면 경고합니다.
  - 같은 말을 반복하는지 검사합니다.
- **판정 기준**
  - 음성 인식: 사람이 읽어서 뜻이 통하는 문장의 비율이 더 높은 쪽
  - 번역: 몽골어가 키릴 문자로 나오고, 오역이 적은 쪽
  - 공통: 전체 메모리 2GB 안에 들어올 것
- **선택 방식**: 언어별로 따로 고를 수 있습니다(예: 몽골어는 NLLB, 중국어·영어는 Hy-MT2). 단, 번역 모델은 한 번에 하나만 메모리에 올립니다.
- **결과 기록**: 이 문서 3장의 표와 `engines.json`에 반영합니다.

## 5. 실시간 파이프라인

```
마이크(miniaudio 캡처, 16kHz 모노)
  → [음성 인식 스레드] 스트리밍 인식 ─ 임시 자막 → UI
                       └ 끝점 감지(말 멈춤) → 문장 조각
  → [문장 정리] SentenceAssembler
       · 군말 제거: "어", "음", "그", "네" 등 조각만 있는 경우 버림
       · 너무 짧은 조각(<8자)은 다음 조각과 이어 붙임 (최대 3초 대기)
       · 너무 긴 조각(>15초 또는 >120자)은 끝맺음 표현(~요, ~다, ~죠)에서 자름
       · 용어 사전(glossary.json) 치환: "노트북 에램" → "NotebookLM"
       · 같은 말 반복 정리: "여러분러분" → "여러분"
  → [번역 스레드] 켜진 언어마다 번역 (요청은 직렬, 큐가 밀리면 오래된 문장의 임시 자막은 건너뜀)
  → UI 확정 줄 추가 (+ 실시간 읽기가 켜져 있으면 TTS 큐)
```

- **반복 방지**
  - NLLB: `no_repeat_ngram_size=3`, `repetition_penalty=1.2`, `max_decoding_length = 입력 토큰 × 2 + 16`
  - Hy-MT2: `max_tokens = 입력 토큰 × 2 + 16`, Tencent 권장값 `repeat_penalty=1.05`, `temperature=0.7`, `top_p=0.6`, `top_k=20`
- **목표 지연**: 말을 멈추고 확정 번역이 뜰 때까지 2초 이내(오프라인 기준). 평가 단계에서 측정합니다.
- **마이크 권장**: 교수님 가까이에 두는 핀마이크나 USB 마이크. README에 적습니다.

## 6. 메모리 예산 (오프라인, 전부 켰을 때)

| 구성 | 목표 | 근거 |
|---|---|---|
| UI와 파이썬 | 약 50MB | 추정 |
| 음성 인식 | 약 350MB 이하 | Zipformer int8 추정 300~400MB |
| 번역 (한 번에 하나만) | 약 1.4GB 이하 | Hy-MT2 Q4 약 1.4GB (제3자 측정, 컨텍스트 2048), NLLB는 실측 약 1.0~1.4GB |
| TTS | 약 150MB | 켜진 언어 모델만, 처음 쓸 때 불러옴. 3개 언어 모두 올리면 약 440MB(실측) |

메모리를 줄이는 규칙은 다음과 같습니다.

- 모든 모델은 처음 쓸 때 불러옵니다. 프로그램을 켤 때는 아무 모델도 올리지 않습니다.
- 온라인 모드에서는 오프라인 번역과 TTS 모델을 올리지 않습니다. 자동 전환할 때만 올립니다.
- 오프라인 TTS 모델은 마지막으로 쓴 뒤 60초가 지나면 내립니다.
- 번역 모델은 하나만 올립니다. 언어별로 엔진이 다르면, 다른 엔진이 필요할 때 기존 모델을 내리고 새로 올립니다.
- llama.cpp 컨텍스트는 1024 토큰으로 둡니다.
- CI 스모크 테스트에서 최대 메모리가 2GB를 넘으면 빌드를 실패 처리합니다.

```
│  │  └─ glossary.py       # 용어 사전 치환
│  ├─ translate/
│  │  ├─ base.py           # Translator 프로토콜: translate(text, lang) -> str
│  │  ├─ mymemory.py
│  │  ├─ nllb.py           # CTranslate2
│  │  ├─ hymt.py           # llama-cpp-python
│  │  └─ router.py         # 모드·언어별 엔진 선택, 실패 시 오프라인 전환
│  ├─ tts/
│  │  ├─ base.py           # Speaker 프로토콜: synth(text, lang) -> Audio(PCM, sample_rate)
│  │  ├─ edge.py           # edge-tts mp3 → miniaudio 디코딩
│  │  ├─ sherpa.py         # sherpa-onnx, 몽골어 글자 치환
│  │  └─ router.py
│  ├─ audio.py             # miniaudio 재생과 정지 (한 번에 하나)
│  ├─ pipeline.py          # 마이크 → 인식 → 정리 → 번역 → UI 연결 (스레드와 큐)
│  └─ ui/
│     ├─ app.py            # CustomTkinter 메인 창
│     └─ display.py        # 번역 전용 창 (CTkToplevel, 글자 크기 조절)
├─ assets/ phrases.json, glossary.json, engines.json
├─ tools/ evaluate.py, download_models.py, build_phrase_audio.py, models.lock.json
├─ packaging/sukpago.spec  # PyInstaller onedir
├─ tests/                  # pytest
└─ .github/workflows/ ci.yml, release.yml
```

**경계 규칙**

- UI는 `pipeline`, `translate.router`, `tts.router`만 호출합니다.
- 엔진 모듈끼리는 서로 모르고, `engines.py`가 엔진을 만들어 넘겨줍니다.
- 스레드는 세 개입니다: 음성 인식, 번역, TTS. 각 스레드는 `queue.Queue`로 일을 받고, 결과는 Tk `after()`로 UI 스레드에 넘깁니다. UI는 막히지 않습니다.
- 모든 엔진은 가짜(fake) 구현을 만들 수 있게 프로토콜로 정의합니다. 테스트는 가짜 엔진으로 돌립니다.

## 9. 오류 처리

| 상황 | 동작 |
|---|---|
| 온라인 번역 실패 (타임아웃 5초, HTTP 오류, `quotaFinished`) | 그 요청은 오프라인으로 처리하고 상태 표시줄에 알림 |

| 모델 파일 없음 | 해당 기능만 비활성화하고 "models 폴더 확인" 안내 |
| 번역이 밀림 (큐에 3개 이상 쌓임) | 상태 표시줄에 "번역 지연" 표시. 확정 문장은 버리지 않음 |

| 재생 장치 없음 | 소리 없이 화면에만 표시하고 알림 |

## 11. CI/CD (GitHub Actions)

**`ci.yml`** (`pull_request`와 `main` 푸시에서 실행)

- `windows-latest`에서 `astral-sh/setup-uv`를 실행합니다.
- `uv sync --locked`, `uv run pytest`를 차례로 실행합니다.
- 모델과 네트워크 없이 가짜 엔진으로 테스트합니다.

**`release.yml`** (태그 `v*` 푸시 또는 `workflow_dispatch`)

1. `windows-latest`에서 checkout, uv 설치, `uv sync --locked`를 실행합니다.
   - llama-cpp-python은 공식 CPU wheel 저장소를 `[[tool.uv.index]]`로 등록해서 받습니다.
2. `actions/cache`로 `models/`를 캐시합니다.
   - 캐시 키는 `tools/models.lock.json`의 해시입니다.
   - 캐시가 없으면 `tools/download_models.py`로 받고 SHA256을 검증합니다.
   - 모델 URL은 리비전 해시로 고정합니다.
3. `tools/build_phrase_audio.py`로 고정 문장 wav를 만듭니다.
4. 스모크 테스트를 실행합니다. 실제 모델로 다음을 각각 1회씩 돌리고, 최대 메모리(psutil)를 기록합니다. 2GB를 넘으면 실패 처리합니다.
   - 녹음 wav 10초 인식(공개 가능한 테스트 음성, 강의 녹음 아님)
   - 오프라인 번역 1문장
   - 언어별 TTS 1문장
5. `pyinstaller packaging/sukpago.spec`로 onedir 빌드를 합니다.
6. `dist/SukPaGo/`에 `models/`, `assets/`, `THIRD_PARTY_NOTICES.txt`, `README.txt`(사용법과 마이크 권장)를 넣습니다.
7. 결과를 `SukPaGo-<버전>-win64.zip`으로 묶습니다.
   - 기본 zip에는 `engines.json`에서 선택된 엔진의 모델만 넣습니다.
   - 예: Hy-MT2 1.13GB + 음성 인식 약 0.2GB + TTS 약 0.17GB + 런타임 약 0.2GB = 약 1.7GB. 모델 파일은 거의 압축되지 않습니다.
   - 대체 엔진 모델(NLLB 0.63GB 등)은 `SukPaGo-<버전>-extra-models.zip`으로 따로 묶습니다.
8. 결과물을 올립니다.
   - `actions/upload-artifact`로 업로드합니다.
   - 태그 빌드는 `softprops/action-gh-release`로 Release에 첨부합니다.
   - Release 파일 하나는 2GB 이하여야 합니다. zip을 만든 뒤 크기를 검사해서, 넘으면 빌드를 실패 처리합니다.
9. 외부 액션은 커밋 SHA로 고정합니다.

## 12. 테스트

- **단위 테스트(pytest, 가짜 엔진)**
  - 고정 문장 표: 5문장 × 3언어
  - 언어 코드 표
  - 몽골어 글자 치환
  - SentenceAssembler: 군말 제거, 이어 붙이기, 자르기, 반복 정리
  - 용어 사전 치환
  - 라우터: 온라인 성공, 실패 시 오프라인 전환, 둘 다 실패
  - MyMemory 응답 파싱: 정상, `quotaFinished`, HTTP 오류
  - ModelManager: 번역 모델은 한 번에 하나만 올라가는지
  - 설정 저장과 불러오기
  - 파이프라인: 가짜 인식기가 문장을 내보내면 UI 콜백까지 도달하는지
- **평가(4장)**: `tools/evaluate.py`로 실제 강의 녹음을 돌립니다. 로컬에서만 실행하고, 결과는 이 문서에 기록합니다.
- **스모크(CI)**: 위 release 4단계.
- **수동 확인(윈도우 PC)**
  - 압축 풀고 실행
  - 맨 앞 표시
  - 마이크로 실시간 번역
  - 온라인/오프라인 전환
  - 네트워크를 끊었을 때 자동 전환
  - 소리 재생
  - 작업 관리자에서 메모리 확인

## 13. 범위 밖

- 학생→교수님 방향 번역
- 화자 구분
- 요약이나 문장 다시 쓰기(큰 언어 모델이 필요함)
- 설치 프로그램(msi)
- 자동 업데이트
- 다른 언어 추가
